# ADR-0006: 録画ファイルもアップロードするファイルも `work_dir` の中に限る

- Status: Accepted
- Date: 2026-09-22
- Amends: [ADR-0005](0005-work-dir-contract.ja.md)

## Context

ADR-0005 は、ファイルを書くすべてのツールで `work_dir` を必須にした。組織の契約
（ADR-021）の一覧でも、このサーバーは対応済みとされている。ところが、ファイルを
指す引数が 2 つ、その外に残っていた。

1. **`screencast_start` の `filePath`。** 検査は末尾が `.gif` かどうかだけだった。
   呼び出し側は、プロセスが書き込める場所ならどこでも指定できた。途中のディレクトリは
   作られ、既存のファイルは上書きされた。ADR-021 §7 は、書き込みは `work_dir` の中
   だけとし、「このフリートに、サーバーがほかの場所へ書く必要のある作業はない」と
   定める。それ以外への書き込みは、モデルの一言で開く持続化の経路（シェルの設定
   ファイル、git hook、launchd の plist）になる。
2. **`upload_file` の `filePath`。** 検査は存在するかどうかだけで、ディレクトリも
   通り、パスはそのまま Chrome に渡っていた。まさにこのために `internal/workdir` が
   持つ認証情報の一覧は、一度も参照されていなかった。ADR-021 §7 の例外は、ファイルを
   マシンの外へ送り出せるものに渡すサーバーを扱い、「入力は `work_dir` の中からだけ
   取る」と定める。Web ページのファイル選択欄はまさにそれにあたる。ファイルの行き先は
   ページが決める。

どちらの挙動もテストが固定していた（`TestScreencastFilePathBeatsWorkDir` は、あえて
`work_dir` の外に書いていた）。意図的な例外だと記録した文書は無い。ADR-0004 の
「意図的に境界にしない」は ADR-021 より前の記述で、同じ日に ADR-0005 が置き換えている。

## Decision

1. **`screencast_start` の `filePath` は `work_dir` の中の場所を指す。** 相対パスは
   `work_dir` からの相対とする。絶対パスは `work_dir` の中になければならず、
   ディレクトリの綴りは呼び出し側が渡したままでも、シンボリックリンクを解決した
   形でもよい。検査はパス上にすでにあるシンボリックリンクをすべてたどり、パスを
   指定した呼び出しである `screencast_start` で、フレームを 1 枚も集める前に行う
   （ADR-0004 の規律）。ファイルは、開始時に `work_dir` を根として開き停止まで保持する
   `os.Root` を通して書く。その間に、書き込みをディレクトリの外へ運ぶシンボリック
   リンクが現れても `os.Root` が拒み、開始時に開いているので `work_dir` 自体がリンクに
   すり替えられてもそれをたどらない。リンク先の無いリンクはリンク先で判定する
   （それを通して作れば、リンク先が作られるため）。
2. **`upload_file` は `work_dir` を必須で受け取り、その中のファイルだけをページに
   渡す。** `filePath` は `work_dir` からの相対パスか、その中を指す絶対パスとする。
   ファイルの実体のパスが `work_dir` の中にあり、認証情報の一覧に当たらず、通常の
   ファイルでなければならない。Chrome に渡すのはその実体のパスである。一覧の検査を
   先に、パスの両方の綴りで行う（ADR-021 §7）。そのため、`work_dir` から `~/.ssh` を
   指すリンクは、単に外にあるファイルとしてではなく、認証情報のファイルとして拒まれる。
3. **`work_dir` の中でも、いくつかの場所は読み書きどちらも拒む。** 認証情報の一覧
   （`sensitive_path`）と、保護するディレクトリ —— このサーバー自身のディレクトリ
   （`config.toml` と管理下のプロファイル）、操作中の Chrome のプロファイル、一時
   ディレクトリにある使い捨ての `chrome-pilot-mcp-profile-*` すべて（ランタイムごとに
   サーバーが動き、強制終了されたものはプロファイルを残す）（`server_dir`）、利用者自身の
   Chrome のプロファイル（`browser_profile`）。`work_dir` がそのどれかの親（一時
   ディレクトリ、`~/.config`、`~/Library/Application Support`）であることは正当にあり得て、
   その場合その下のファイルは稼働中のプロファイルの Cookie になる。その中を指す
   `work_dir` は `work_dir_denied` で拒む。保護するディレクトリは名前ではなく
   **ファイルの実体**で比べる。APFS は既定で大文字小文字を区別せず、文字列の比較では
   `CHROME-PILOT-MCP/profiles/…/Cookies` が通った（2 回目のレビュー）。3 回目のレビューは
   使い捨てのプロファイルが守られていないことを見つけた。
4. **このサーバーが書くファイルはすべて `writeUnder` を通る。** `os.Root` を通すので
   `work_dir` の外へのリンクは拒まれる。ディレクトリを作る前に、リンクをたどった先の
   場所を検査し、作った後にもう一度 —— root が届くディレクトリがパスの指すものと同じか、
   保護された場所でないか —— を検査する。そのため、保護された場所へのリンクになった
   `screenshots/`・`screencasts/` は、空のディレクトリ 1 つ作られることなく拒まれ、録画中に
   動かされた `work_dir` には書かずに拒む。推測できない固定長の一時名で排他的に作ってから
   名前へ移すので、既存のエントリ（`work_dir` の外のファイルへのハードリンクを含む）は
   書き込み先としてたどらず置き換え、予測できる一時名に仕込まれたものを通して書くこともない。
   リンク先が `..` で上る、リンク先の無いリンクはたどらずに拒む。つなげると、ある部分が
   それ自身のリンクを解決される前に名前だけで打ち消されてしまうため。
5. **拒否は `path_not_allowed`** とし、どの規則に当たったかを `details.reason` で
   示す（`outside_work_dir`・`sensitive_path`・`server_dir`・`browser_profile`）。ファイルが
   無い場合とディレクトリの場合は、これまでどおり `invalid_arguments`。
6. `os.Root.MkdirAll` を使うため、`go.mod` を Go 1.25 に上げる。依存は引き続き
   標準ライブラリだけ。

## Consequences

- **互換を崩す。** `work_dir` の無い `upload_file` は `work_dir_required` で拒まれる。
  どこからでもアップロードしていた呼び出し側は、先にファイルを作業ディレクトリへ
  コピーする必要がある。`work_dir` の外を指す `screencast_start` は、開始の時点で
  拒まれる。すべての呼び出しに `_meta["jp.nlink/work_dir"]` を付けるランタイムは、
  `upload_file` の呼び出しを変えなくてよい。
- 相対パスの `filePath` は、これまでサーバー自身の作業ディレクトリからの相対だった。
  今は `work_dir` からの相対になる。シンボリックリンクを含むディレクトリで綴った
  絶対パスの `filePath` は、解決後のパスで返る。
- `upload_file` は `uploaded` にファイルの実体のパス、つまり Chrome に渡したパスを
  返すようになった。シンボリックリンクなら、ページに見えるのはリンク先の名前。
- **絶対パス**のシンボリックリンクである `screencasts/`・`screenshots/` は、
  `work_dir` の中を指していても `workspace_failed` で失敗するようになった。
  `os.Root` は絶対パスのリンクを拒むため。`work_dir` の中を指す相対パスのリンクは使える。
- `internal/workdir` は変えていない。規則は `internal/tools/confine.go` に置く。
  書くファイルのモードは常に `0644` になった。
- **これで塞がらないもの。** Chrome にはパスを渡し、Chrome が後でファイルを開くため、
  検査の後にファイルがリンクへすり替えられると、リンク先が読まれる。
  `DOM.setFileInputFiles` が受け取るのはパスで、開いたファイルではない。`work_dir` の
  外のファイルへのハードリンクのアップロードは検出しない（ADR-021 も求めていない）。
  一覧との比較は大文字小文字を区別するため、大文字小文字を区別しないファイルシステムでは
  `.ENV` や `~/.SSH` が一覧をすり抜ける。これはフリートで共有する `internal/workdir` の
  問題で、ここではなくそちらで直す。`screencast_stop` を呼ばずに放置された録画は、
  プロセスが終わるまでフレームとディレクトリのハンドルを 1 つ持ち続ける。接続（attach）した
  ブラウザのプロファイルはこのサーバーには分からず、利用者自身の Chrome の場所以外は守らない。
